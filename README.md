# OoKoo PPT Studio

第一版：输入一句话主题及补充说明，页数可选 1～20 页（默认 5 页）、16:9、简体中文。Node.js 直接调用百炼 Qwen 规划精简文案和逐页构图，再生成含文字的完整幻灯片图片。网页原图预览；PPTX 每页一张高清图，PDF 同样保持整页视觉。

视觉参考用户提供的小米发布会 PDF：大图、极简标题、重点数字、产品特写及黑白交替。将超宽画面重组为 16:9；不复用小米品牌、Logo 和产品图片。新建真实项目使用整页图片模式；生图前仅展示明确标注的大纲草稿。旧项目和历史排版示例仍保留原模式，不代表新版视觉效果。

## 本地使用

- 工作台：http://localhost:3210/
- 文本模型固定为 `qwen3.8-max`，使用百炼北京兼容接口。
- 图片模型默认配置为 `qwen-image-2.1-pro`，使用百炼北京原生异步接口；北京原价 0.25 元/张，五页图片约 1.25 元，另计文本费用。实际账单取决于免费额度及优惠。

当前架构为：网页 → Node.js → 百炼 Qwen。内容规划、单页修改、图片生成均直接调用百炼，不需要 Dify。页面左上角使用 OoKoo LOGO。本地验收记录及样稿存放于 `artifacts/`，不上传 GitHub；真实项目、凭据和生成图片存放于被忽略的本地目录。Docker 构建此前因镜像仓库连接中断未通过。

需要 Node.js 22.12+ 或 24 LTS、Chrome/Chromium。首次安装：

```sh
git clone https://github.com/kamirui9/ookoo-ppt-studio.git
cd ookoo-ppt-studio
npm ci --ignore-scripts
npm start
```

推荐使用 Node.js 24 LTS（`.nvmrc` 已固定主版本）。本机系统默认 Node.js 23 已停止支持，当前 Codex 验收服务使用已安装的 Node.js 24.19.0；未修改系统默认版本。自行后台启动时可通过 `NODE_BIN=/绝对路径/node sh scripts/start-local.sh` 指定运行时。

如果希望在自己的终端后台启动：`sh scripts/start-local.sh`。停止自建后台进程：`sh scripts/stop-local.sh`。Codex 验收期间也可能通过持续终端会话运行，请先检查 3210 端口，避免重复启动。

首次运行自动生成 `.env`，权限 600。只在该文件填写 `BAILIAN_API_KEY`。配置保存后自动读取；绑定地址、端口修改需重启。前端和项目文件中不存储 API Key。请不要分发 `.env` 或整个 `data` 目录（含私有归档）。

## TypeScript 开发与编译

```sh
npm run typecheck   # 分别严格检查前后端，不生成文件
npm run build       # 编译到 dist/，任何类型错误都会阻止输出
npm start           # 自动先编译，再运行 dist/server.js
npm test            # 自动先编译，再运行隔离测试
```

后端编译结果为 `dist/server.js`、`dist/lib/*.js`；前端为 `dist/client/public/app.js`，仍通过 `/app.js` 提供给浏览器。HTML 和 CSS 不需要编译。`dist/` 是可重新生成的产物，不应手动编辑。前后端启用 `strict`、`noEmitOnError`，没有引入 Vue/React/Next.js。TypeScript 编译器和 Node 类型包为开发依赖；Docker 使用多阶段构建，运行阶段不安装编译器。

测试使用临时配置和临时数据目录，模型接口采用模拟响应，不读取真实 `.env`，不访问真实项目数据，也不会产生模型费用。`LAUNCH_ENV_FILE`、`LAUNCH_DATA_DIR` 仅用于隔离测试或明确指定本地配置/数据位置。

## 操作流程

1. 输入一句话主题和补充说明，选择页数（1～20，默认 5），点击“生成 PPT”。16:9，默认白底；想要黑底等风格可直接写在补充说明里。
2. 确认一次生图张数及费用后，自动规划内容并生成全部页面。无需大纲确认、代表页确认或手动选择版式。生成过程显示进度；失败后可“继续生成”，已完成页面会保留。
3. 点击页面缩略图预览。需要修改时，在“修改这一页”输入自然语言要求，点击“更新这一页”；确认单张费用后，自动改写并重新生图，不需单独保存。
4. 点击“下载 PPT”。未完成整套时，按钮明确显示可下载的页数。PPT 每页为一张图片，文字不单独可编辑。

补充说明填写受众、演讲时长、真实资料和整体视觉要求。选择页数后，“每页内容”显示对应数量的独立输入框，每框可填写该页主题、关键内容或指定文案；留空的页由模型自动规划。每页最多 2000 字。临时减少页数再增加，当前页面中已填内容会保留；提交时仅包含所选页数以内的输入。

例如选择 3 页，补充说明写“面向新员工，白底发布会风格”，再分别填写：

- 第 1 页：封面，标题为「让 AI 成为你的工作搭档」
- 第 2 页：介绍整理会议纪要、起草邮件、总结文档三个场景
- 第 3 页：用一个实际案例讲解操作步骤

逐页内容通过独立字段传入模型，补充说明不再自动识别页码。实际文案和图片仍需检查模型生成结果。

简化网页不再展示详细参数、上传图片、版本操作或 PDF 下载；原有后端接口和历史数据保留。演示列表仍可从“我的演示”打开。

整页生图使用唯一文案清单：品牌文字与标题一同指定，清除构图中被引用的禁止词句，减少模型额外画字的机会。这个措施仍需实际生图检验，不能保证消除所有错字。

生成后需检查中文是否准确、有无错字、主体构图和图中文字是否拥挤。整页图片提升视觉自由度，但不能保证模型永远正确输出中文。修改文字需再次生图、再次计费。

百炼明确返回 HTTP 429 且没有受理任务 ID 时，会按 15 / 30 / 60 秒等待、最多重试三次；响应的 Retry-After 要求更长等待时按其执行，单次超过 120 秒则停止并提示稍后继续。查询任务遇到 429 也会等待重试，继续使用原任务 ID。提交结果未知的网络错误仍不自动重投。图片提交按模型在本进程内统一间隔，3.0 Pro 默认至少 13 秒，其余型号至少 4 秒；可设置 IMAGE_MIN_INTERVAL_MS 提高间隔。这是本地节流策略，不能保证其他程序共用 Key 时不会达到业务空间限额。

项目自动存储在 `data/projects`，每次保存产生历史快照，可恢复成新版本。当前原型使用浏览器会话隔离项目，同一访问密码下不同浏览器也不会自动共享项目；清除 Cookie 会失去原会话的访问入口。公司部署前接入员工身份及管理员恢复机制。

## 架构与公司部署

- 前端：原生 HTML / CSS / TypeScript，交互源码为 `public/app.ts`。
- 后端：TypeScript / Node.js，原生 HTTP 服务，源码为 `server.ts`、`lib/*.ts`。
- 共享类型：`shared/types.ts` 定义项目、幻灯片、任务、请求及响应。前后端同时引用，模型 JSON 和用户输入仍保留运行时校验。
- 文本和图片：后端直连百炼北京，API Key 仅留在服务器。
- PPTX：PptxGenJS 每页整图；PDF：Chrome/Chromium 原图导出；图片处理：Sharp。旧项目兼容原生文字和形状。
- 项目与历史：本地 `data/projects`；图片任务：单进程内存队列，受理后的百炼任务 ID 持久化。
- 代码按前后端职责划分，目前由同一个 Node.js 服务提供网页与 API。

公司部署不再需要导入 Dify 工作流、配置 Dify 应用 Key、桥接 Token 或 SSRF 白名单。旧接入文件及修改前配置只在本机 `data/legacy-dify` 私有归档；原本地 Dify 实例和应用没有删除或改动。

1. 独立部署本服务。优先使用 Node.js 24 LTS；`Dockerfile` 和 `compose.yaml` 已准备。填好 `.env`，设置强 `APP_ACCESS_PASSWORD`。容器监听全接口时未设访问密码会拒绝启动。Compose 默认只向宿主机 127.0.0.1 发布 3210，由公司 HTTPS 反向代理提供访问。
2. 设置百炼北京 Key，核实业务空间权限、模型 ID、账单与额度。仅支持百炼 Qwen 图像模型；不会调用其他图片平台。
3. 接入公司 SSO、稳定员工 ID、项目授权和访问恢复。当前共享访问密码及 Cookie 隔离是原型功能，尚未实现企业 RBAC/SSO。
4. 备份持久化数据卷和凭据。当前图片队列在单进程中，服务重启标记中断并保留百炼任务 ID；多副本部署前改为 Redis/数据库任务队列与分布式锁。
5. 用 5/8/12 页、长中文、单页改写、上传图片、并发、重启恢复、PDF/PPTX 字体检查完成公司环境验收。

图片任务提交结果不明时不会自动再次提交，避免重复计费。用户可在百炼核实后明确“重新生成图片”；生成失败时旧图片仍保留。模型更新时由管理员核实官方型号再修改配置。

## 验证

`npm test` 覆盖页数约束、文本转义、元素画布边界、错误信息脱敏、项目会话隔离、跨站请求拒绝、版本冲突、单页变更不影响其余页面、排序，以及真实双格式文件导出。浏览器视觉与实际 Qwen 调用另行记录在 `artifacts/validation.md`。

模型接口依据：[百炼 Qwen 图片生成 API](https://help.aliyun.com/zh/model-studio/qwen-image-generation-and-editing-api-reference)。
